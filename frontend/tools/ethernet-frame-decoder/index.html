Ethernet Frame Decoder

Paste the hex bytes of an Ethernet frame and read its layer-2 header: both MAC addresses, every 802.1Q or 802.1ad tag, the EtherType or length field, the LLC/SNAP header, where the payload starts, and whether the last four bytes are a valid frame check sequence.

Fourteen bytes or more: the header plus whatever follows it. Spaces, colons, 0x prefixes and dump offset labels are ignored, so a capture line or a hex dump pastes straight in. The preamble and the inter-frame gap are not part of the frame and must not be pasted.

    Decoded VLAN tags

      Destination and source addresses are six octets each, then two octets that are an EtherType at 1536 and above or a payload length at 1500 and below; 1501 to 1535 is undefined, and the page says so rather than guessing. A tag is four octets: a two-octet tag protocol identifier, 0x8100 for 802.1Q or 0x88a8 for 802.1ad, then a tag control information word holding the three-bit priority code point, the drop-eligible bit and the twelve-bit VLAN identifier, where zero means a priority tag with no VLAN. Tags stack, so the page walks them until the field is no longer a tag identifier. An IEEE 802.3 length field is followed by a three-octet LLC header, and when both service access points are 0xaa with control 0x03 a five-octet SNAP header carries an EtherType of its own. The frame check sequence is the CRC-32 of everything before it, stored least significant octet first: the page reports one only when the last four octets reproduce it, because capture tools normally strip it. The inner protocol line is a summary of the first bytes only — the IPv4, TCP and ICMP decoders read those headers field by field. Everything runs in your browser; nothing is pasted anywhere else.
