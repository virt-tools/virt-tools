ANSI Escape Sequence Decoder

Paste coloured terminal output to see what each escape sequence means and what the text looks like with the codes removed.

paste log or prompt output; real escape characters and the written forms \x1b, \e, \033, \u001b and ^[ are both accepted

Preview



Colour and attribute sequences are applied. Cursor movement, scrolling and erasing are described below but not emulated, and other control characters are shown as their ␀-␟ symbols.








Sequences in order








An escape sequence starts with the ESC character (U+001B) and is one of three shapes: a two-character code such as ESC c for a full reset, a control sequence introduced by ESC [ whose parameters and final letter request a cursor move, an erase or a style, or a string sequence such as ESC ] 0 ; title BEL that carries a title, a hyperlink or a palette colour. SGR sequences — those ending in m — are the ones that set bold, italic, underline, strike-through, reverse and the foreground and background colours, and only those are drawn in the preview; every sequence is still listed with its line and column. Colours are read as the 16 system colours (mapped to the usual VGA palette), 256-colour indices (0–15 system, 16–231 the 6×6×6 cube, 232–255 greys) and 24-bit values, in both the semicolon and colon parameter forms. Reverse video swaps the foreground and background, hidden text is drawn very faintly so it stays visible, and blinking is described but not animated. Nothing is emulated beyond style: a cursor move or an erase does not rewrite the preview, so a progress bar that redraws itself with \r will appear as one line with visible carriage-return symbols. This page reads only what you paste, runs entirely in your browser and never uploads, stores or fetches anything.
