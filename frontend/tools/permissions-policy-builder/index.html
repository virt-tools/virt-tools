      A Permissions-Policy header is a structured-field dictionary: each member names one feature and gives its allowlist. The allowlist is written as a token (* for every origin, self for this origin), as an empty list (), or as a parenthesized list of sources, where every origin is quoted. * and () may only stand alone; self and src may be combined with origins. A source is an origin — scheme, host and port — and may use a wildcard label (https://*.example.com) or a wildcard port (https://example.com:*); a path, query or fragment is not part of one and is refused here rather than silently ignored by the browser. Features left out of the header keep their default allowlist, so this page omits what you do not set instead of writing a permissive entry for it. Duplicate members and duplicate sources are refused or collapsed: a dictionary with a repeated key is invalid, and repeated origins add nothing. Browser support for individual features varies and a name that a browser does not implement is ignored, so the page lists the standardized names it knows and warns about any other. Per-directive report-to endpoints are not modelled. Everything runs in your browser with no storage, uploads or network access.
