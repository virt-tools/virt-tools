Python Version Specifier Checker

Check one Python version against a PEP 440 specifier set — the syntax used by requires-python, pip constraints and package metadata — and see which clause decides the answer.

Comma-separated clauses, each an operator and a version: >=3.9,<4, ~=1.4.2, ==1.4.*, !=1.5.0, ===1.0. A version may carry an epoch (1!2.0), a pre-release (rc1), a post-release (.post1), a dev release (.dev2) and a local label (+ubuntu.1).

    How the version parses

    ComponentValue

    A PEP 440 version is an optional epoch, a release, and optional pre-release, post-release, dev-release and local segments. It is normalized before use: a leading v and separators are dropped, alpha/beta/c/pre become a/b/rc, a hyphen and a number become .postN, and local segments are lowercased. Versions are ordered by epoch, then release with missing segments read as zero, then pre-release (a dev-only release sorts below a0, a final release above rc), post-release, dev release and local label. A clause applies that order: ~=1.4.2 means >=1.4.2 and ==1.4.*; == and != compare releases with zero padding and ignore a local label unless the clause has one; <= and >= ignore the candidate's local label; < and > also refuse a pre-release, post-release or local build of the boundary version itself, and === compares the normalized string literally. A pre-release candidate fails the whole set unless some clause names a pre-release, which is the PEP 440 default that pip can override. A wildcard may only follow an epoch and release numbers, </<=/>/>= take no local label, and ~= needs at least two release numbers. The check runs in your browser; nothing is sent, stored or uploaded.
