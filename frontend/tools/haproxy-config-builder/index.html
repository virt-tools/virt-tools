HAProxy Config Builder

Describe a frontend, its backends and the weighted servers behind them, and get a haproxy.cfg fragment together with the traffic split and health-check failover time it will produce.

Frontend

The first backend below is the default. Routing rules send matching requests to another backend before that fallback applies.

Backends and servers

Weight is relative: servers share traffic in proportion to their weight, as the manual describes. A weight of 0 keeps a server out of new traffic but leaves it available for persistent connections.

Health checks

HAProxy probes each checked server every interval and marks it down after fall consecutive failures, up again after rise successes. These values apply to every checked server; the defaults are the manual's.

Routing rules

Rules are evaluated in order and the first match wins, so a later rule that matches the same value can never be reached. Content matches need http mode; src works in both.

The output is text for you to review, not a validated deployment: it has not been parsed by HAProxy. It does not model TLS termination, cookies or stick tables, DNS service discovery, ACL samples beyond these four, or connection persistence. Run haproxy -c -f haproxy.cfg before loading the file. Everything is computed in the browser: no storage, uploads or network access.
