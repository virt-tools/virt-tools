IPv6 EUI-64 Interface ID Generator

A host that uses stateless address autoconfiguration builds its IPv6 interface identifier from its 48-bit MAC address with the modified EUI-64 rule: flip the universal/local bit and insert ff:fe in the middle. This page does that conversion, combines the identifier with a /64 prefix, and also shows the fe80:: link-local address. Everything runs locally.

Input

Colon, dash, Cisco dotted or plain hex; 12 hex digits for a MAC, 16 for an EUI-64.

Only the first 64 bits are used; any host bits are cleared.

How the modified EUI-64 rule works

Take the 48-bit MAC 00:1a:2b:3c:4d:5e. The first octet's universal/local (U/L) bit is bit 1, the 0x02 place; the multicast (I/G) bit is bit 0, the 0x01 place. Flipping the U/L bit turns 00 into 02, then ff:fe is inserted between the vendor and device halves:

  • 00:1a:2b + ff:fe + 3c:4d:5e becomes 02:1a:2b:ff:fe:3c:4d:5e, written as 021a:2bff:fe3c:4d5e.
  • The link-local address is always fe80::/64 plus that identifier, so this MAC gives fe80::21a:2bff:fe3c:4d5e.
  • A global address puts the chosen /64 prefix in front of the identifier. The tool clears any host bits you type after the 64th bit.
  • An odd first octet (I/G bit set) marks a multicast or broadcast address, which cannot be an interface identifier; the tool rejects it instead of guessing.
  • If you paste a 64-bit EUI-64 identifier, only the U/L bit is flipped — ff:fe is not inserted a second time.
  • Addresses are printed in the RFC 5952 canonical form: lowercase, no leading zeros, and the longest run of zero groups collapsed to ::.
  • Modern operating systems usually prefer stable-privacy or temporary addresses for outbound traffic, so a SLAAC address built this way is the interface's stable identifier, not necessarily the source address it uses.
