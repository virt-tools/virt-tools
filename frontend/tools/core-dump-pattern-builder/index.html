Core Dump Pattern Builder

Enter the value of /proc/sys/kernel/core_pattern and a sample crash, and the page expands the template the way the kernel does — every % specifier replaced, a specifier the kernel does not know dropped with its %, a trailing % removed, and the legacy .PID suffix applied. You get the resulting core file name or the handler command line, each specifier's contribution and the 128-byte limit. Everything runs in your browser; nothing is uploaded, stored or sent anywhere.

Template

A file name template, or a command line when the first character is |. Relative names are resolved against the crashing process's working directory.

      What this does not do

      • This expands a template for the sample values above; it does not read or write /proc/sys/kernel/core_pattern, and it cannot tell which value your kernel actually holds.
      • Whether a file appears also depends on the core size limit, a writable directory, a filesystem with space and inodes, a readable executable, and fs.suid_dumpable for set-user-ID or file-capability programs.
      • A path is interpreted in the crashing process's root directory, working directory and mount namespace, so an absolute name here may land elsewhere for a containerised process.
      • Many systems hand dumps to systemd-coredump, which installs its own pipe template; this page explains a template, it does not replace coredumpctl.
      • The pattern field is capped at 512 characters here, and names over 128 bytes are flagged rather than silently shortened. core(5) gives 128 bytes as the maximum resulting name; the kernel sysctl documentation gives the pattern file itself a maximum length of 127 characters.
