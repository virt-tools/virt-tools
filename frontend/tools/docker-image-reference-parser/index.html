Normalization notes

    How a reference is split

    • Digest first. Everything after @ is a digest of the form algorithm:encoded. A digest pins exact content, so a reference that has one does not need a tag.
    • Then the tag. A colon after the last slash introduces a tag. Colons before the last slash belong to a registry port, which is why localhost:5000/app is registry localhost:5000 with no tag.
    • Then the registry. The first path component is a registry when the reference has more than one component and that component contains a dot or a colon, is localhost, or is a bracketed IPv6 address. Without one, Docker uses docker.io.
    • Then normalization. index.docker.io and registry-1.docker.io are aliases of docker.io; a single-component Docker Hub name gains the library/ namespace; and a reference with neither tag nor digest resolves to the moving tag latest.
    • Limits. Names are lowercase and at most 255 characters, path components allow single ., _ or - separators, and tags are at most 128 characters. A sha256 digest must carry 64 hexadecimal characters and a sha512 digest 128; other algorithms are accepted but not length-checked.
    • This is a parser for reference syntax and Docker's client-side normalization. It does not contact a registry, verify that the image exists, or check whether the tag exists. Everything runs in your browser with no storage, uploads or network requests.
