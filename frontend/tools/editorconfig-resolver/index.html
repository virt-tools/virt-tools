EditorConfig Settings Resolver

Which properties a file actually gets, and which section line decided each one.

EditorConfig file and paths

Sections in [square brackets] hold key = value pairs. Later sections override earlier ones, and unset clears a property again.

One path per line, relative to the directory that holds this .editorconfig. Use / separators.

Effective settings

EditorConfig cores read every matching section top to bottom, so the last value for a property wins. A section name containing a / is anchored to this file's directory; one without a / matches at that level and below. * and ? never cross a slash and ** does, but the slashes written around ** stay literal, so a/**/b needs a directory level between a and b. {a,b}, {1..4} and [seq] are supported, a - inside a class is a literal dash in the specification rather than a range, and a section name ending with / matches nothing. Only the pasted file is read: parent .editorconfig files, root search and editor integration are out of scope, and nothing is uploaded, stored or fetched.
