yEnc Encoder / Decoder

yEnc is the transfer encoding used for binary attachments in Usenet: every byte is shifted by 42, a handful of characters are escaped with =, and the trailer carries the byte count and a CRC32 checksum. Encode text into a postable body, or paste a yEnc body and decode it while the size and checksum are verified. Everything runs in your browser; nothing is uploaded.

    How yEnc works

    Each payload byte is stored as (byte + 42) mod 256, so the characters that would break a Usenet message — NUL, LF, CR and = — never appear unescaped. When the shifted character is one of those, or a tab or space at the start of a line, it is written as = followed by (character + 64) mod 256. A decoder subtracts 106 from the escaped character instead of 42.

    • =ybegin line=128 size=N name=file opens the part; =ypart marks a multipart section; =yend size=N crc32=XXXXXXXX closes it.
    • Line breaks inside the body are framing and are removed before decoding, so the body can be reflowed by a news client.
    • The CRC32 is the standard IEEE 802.3 checksum (same polynomial as zip and PNG) over the original bytes, shown as eight lowercase hex digits.
    • This page encodes the UTF-8 bytes of the text you type. When a decoded payload is not valid UTF-8 it is shown as hex rather than silently replaced.
    • Input is limited to 100,000 characters, which keeps encoding and checksumming in a single frame. Nothing is stored and no request is made.
