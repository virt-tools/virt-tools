POSIX ACL Effective Rights

Paste ACL entries — the output of getfacl, or the short form you would hand to setfacl — and see what each entry really allows once the mask is applied, which mode ls -l will print, and where a grant is being quietly cut down. Everything is worked out in your browser; nothing is uploaded, stored or sent anywhere.

ACL entries

Three colon-separated fields: tag, qualifier, permissions. Tags are user/u, group/g, mask/m and other/o; default: prefixes a default entry. Up to 32 entries.

    What this does not do

    • It explains the entries exactly as you paste them. It reads no file, checks no account, and cannot tell whether the filesystem or mount actually supports ACLs.
    • It does not run setfacl or chmod: the command line it prints is for you to review and run yourself.
    • When the mask is left out, setfacl recalculates it unless -n is given, so the mask stored on disk can differ from the one shown here. The canonical form above always writes the mask explicitly, which keeps setfacl from changing it.
    • NFSv4 ACLs (deny entries, inheritance flags) and SELinux or AppArmor are different mechanisms and are not modelled.
    • Default entries are validated and listed, but the ACL of a newly created file is not computed: inheritance also applies the creation mode and umask.
    • Everything stays in this page: no upload, no account, no network request, no storage.
