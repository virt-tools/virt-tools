HTTP Precondition Evaluator

Paste the validators a resource currently has and the conditional headers a request sends, and see whether the request proceeds, is answered 304 Not Modified, or fails with 412 Precondition Failed — evaluated in the order RFC 9110 gives, with every ignored header explained. Everything runs in your browser; no request is made and nothing is stored.

Request and resource

The evaluator models an origin server that is receiving the request for one target resource. Leave a conditional header empty to leave it out of the request.

    What this does not do

    • It models one origin server evaluating the four preconditions from RFC 9110 sections 13.1.1 to 13.1.4 on one target resource. It does not send a request, follow redirects, or show what the method itself would return.
    • Only the IMF-fixdate form (Sun, 06 Nov 1994 08:49:37 GMT) and the asctime form (Sun Nov 6 08:49:37 1994) are read; the obsolete RFC 850 two-digit-year form is refused rather than guessed.
    • Range requests and If-Range are not evaluated, so the 206 outcome of a partial request is out of scope.
    • Nothing is saved and no account is needed: reloading the page clears the fields.
