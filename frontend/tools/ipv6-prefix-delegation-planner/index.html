IPv6 Prefix Delegation Planner

Split a delegated IPv6 prefix into per-site prefixes: how many sites fit, the /64 subnets each one gets, and the exact address range of every site.

The block your provider delegated, with its length — for example 2001:db8:1200::/48. The address must be the first address of the block.

/56 is the usual home or branch delegation. IPv6 subnets are /64, because interface identifiers are 64 bits long.

How many sites you want laid out, from 1 to 1,000, up to what the delegation holds.

Site prefixes

Each site prefix and the /64 subnets inside it, in order.

An IPv6 delegation is split on power-of-two boundaries. A delegated prefix of length D carved into site prefixes of length S, with D ≤ S ≤ 64, yields 2^(S−D) site prefixes, each holding 2^(64−S) subnets of length /64, so the whole delegation holds 2^(64−D) of those /64 subnets. IPv6 expects a subnet to be a /64 because interface identifiers are 64 bits long (RFC 4291, Section 2.5.1); that is why the planner reports the /64 range inside each site and refuses a site prefix longer than /64. /56 is the default because RFC 6177, the current best-current-practice guidance on address assignment to end sites, recommends giving a site significantly more than a single /64 and names /56 as a reasonable default for home sites, while /48 remains common for larger sites. A delegation normally arrives over DHCPv6 as an Identity Association for Prefix Delegation (RFC 8415, which folded in RFC 3633), and this page only lays the received block out: it does not talk to a router, does not verify that the block is yours, and does not configure DHCPv6, router advertisements, SLAAC, routing or firewall rules. The address entered must be the first address of its block; a prefix with host bits set is refused, and the aligned block is reported so you can correct it. Everything runs in your browser with no uploads, storage or network requests.
